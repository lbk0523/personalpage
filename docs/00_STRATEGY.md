# Personal Page Strategy

Status: APPROVED  
Approved: 2026-08-19

## 1. 존재 이유

이병관이 해온 일과 만든 것, 현재의 관심, 살아가며 발전시키는 생각을 자신의 이름 아래 장기간 축적하고 세상과 공유하는 개인 웹사이트를 운영한다.

이 사이트는 단순한 취업용 포트폴리오나 일반적인 블로그가 아니다.

장기간에 걸쳐 다음을 한곳에 축적한다.

- 직업적 경력과 역량
- 직접 수행한 프로젝트
- 일하면서 형성한 관점
- 개인적으로 탐구하고 만드는 것
- 삶을 살아가며 생기는 생각과 변화

사이트는 현재의 나를 설명하는 명함, 과거의 나를 보여주는 기록, 앞으로의 나를 축적하는 공간의 역할을 함께 한다.

## 2. 사이트 정체성

사이트의 상위 개념은 특정 직무나 개별 브랜드가 아니라 **이병관이라는 사람**이다.

현재의 핵심 직업적 정체성은 게임 사업 PM이지만, 사이트 전체를 한 직책에 고정하지 않는다.

권장 정체성 위계는 다음과 같다.

1. 이병관
2. 현재는 게임 사업 PM으로 일한다.
3. 제품·시스템·사람이 움직이는 방식을 고민한다.
4. 생각하고, 구조화하고, 직접 만들어보고, 기록한다.

처음 방문한 사람에게는 먼저 “무엇인가를 생각하고 구조화하며 직접 실행하는 사람”이라는 인상을 주고, 그다음 현재 그 전문성이 게임 사업 영역에서 가장 많이 발휘되고 있음을 이해하게 한다.

## 3. 사이트의 핵심 기능

### A. Work — 증명

“나는 무엇을 해봤는가”를 보여준다.

단순 이력 나열보다 실제 문제 해결 경험과 판단 과정을 중심으로 구성한다.

기본 케이스 구조는 다음을 지향한다.

- 상황과 목표
- 내 역할
- 핵심 제약
- 내가 발견한 문제
- 검토한 선택지와 판단
- 실행 과정
- 결과 또는 확인된 변화
- 다음에 다르게 할 점

### B. Writing — 사고

“나는 무엇을 생각하는가”를 보여준다.

주제는 특정 전문 영역으로 제한하지 않는다.

현재 예상되는 주요 주제는 다음과 같다.

- 게임 / 사업 / 제품
- AI와 일하는 방식
- 생산성 / 시스템 / 프로세스
- 개인 프로젝트
- 삶
- 육아

`아빠들의 육아 대화`는 Writing 내부의 연재/주제로 다룬다. 독립 사이트나 상위 브랜드로 분리하지 않는다.

콘텐츠 완성도에 따라 다음 두 형식을 허용한다.

- **글**: 하나의 생각을 어느 정도 정리한 콘텐츠
- **노트**: 관찰, 질문, 짧은 생각, 아직 결론 내리지 않은 콘텐츠

### C. Now — 현재

“나는 지금 무엇을 하고 있는가”를 보여준다.

다음과 같은 내용을 짧게 담는다.

- 현재 하는 일
- 최근 관심을 두고 탐구하는 것
- 진행 중인 개인 프로젝트
- 최근 삶에서 중요해진 것

정적인 포트폴리오와 현재의 활동을 연결하는 역할을 한다.

## 4. 대상 독자

### 1차 독자

앞으로 이병관과 어떤 형태로든 함께 일할 가능성이 있는 사람.

예:

- 동료
- 다른 업계 실무자
- 미래의 채용 담당자·면접관
- 프로젝트 협업자
- 사업·제품 관계자

이들이 사이트를 통해 “이병관은 어떤 경험이 있고 어떤 식으로 생각하는가”를 이해할 수 있어야 한다.

### 2차 독자

글 자체를 통해 이병관과 생각을 교환할 사람.

게임, 시스템, 생산성, 육아 등 서로 다른 주제에서 유입될 수 있다.

### 3차 독자

미래의 나와 가족.

공개 가치가 있는 기록을 통해 시간이 지나며 생각과 관심이 어떻게 변화했는지 돌아볼 수 있어야 한다.

## 5. 사이트가 보여주고 싶은 인상

### 1) 생각하는 사람

업무 결과만이 아니라 왜 그렇게 판단했는지가 보인다.

### 2) 실행하는 사람

생각에 머물지 않고 직접 만들거나 실행한 흔적이 있다.

### 3) 계속 변화하는 사람

완성된 전문가처럼 포장하기보다 배우고 생각이 변하는 과정이 보인다.

### 4) 직업 밖에도 삶이 있는 사람

육아와 삶의 글은 전문성을 희석하는 장식이 아니라, 어떤 삶을 살면서 어떤 판단을 형성하는 사람인지 보여주는 층이다.

## 6. 콘텐츠 원칙

### 원칙 1. 모든 글이 전문적일 필요는 없다

육아 글을 PM이나 업무 인사이트에 억지로 연결하지 않는다.

사이트 전체를 묶는 것은 주제가 아니라 저자다.

### 원칙 2. 완성도가 다른 글을 허용한다

글과 노트를 분리해, 아직 결론이 나지 않은 생각도 공개할 수 있게 한다.

### 원칙 3. 실제 경험에서 출발한다

일반적인 정보 블로그가 되지 않도록 경험, 질문, 판단을 중심에 둔다.

예:

- 덜 적합: `생산성을 높이는 7가지 방법`
- 더 적합: `할 일이 많을수록 시스템을 더 만들고 싶어지는 문제가 있었다`

- 덜 적합: `6개월 아기와 가기 좋은 곳 TOP 10`
- 더 적합: `6개월 아기와 매주 카페만 가던 우리가 외출을 다시 생각하게 된 이유`

정보를 제공할 수는 있지만 사용자의 경험·질문·판단이 중심이어야 한다.

## 7. 공개와 비공개의 경계

### 공개한다

- 내 경험
- 내 판단
- 내 실패
- 공개 가능한 업무 이야기
- 개인 프로젝트
- 가족생활에서 내가 느끼고 배운 것

### 공개하지 않는다

- 회사의 비공개 정보
- 동료가 특정될 수 있는 갈등
- 배우자의 동의가 필요한 사적인 내용
- 아이가 커서 원치 않을 가능성이 높은 정보
- 아이의 건강·발달·생활상의 민감 정보
- 분노나 감정이 충분히 정리되지 않은 상태에서 특정 사람을 다루는 글

기본 원칙:

> 내 이야기는 내가 결정해서 공개할 수 있지만, 다른 사람의 이야기는 내 콘텐츠 재료라고 가정하지 않는다.

육아 콘텐츠의 기본 주어는 아이가 아니라 아빠인 나로 둔다.

## 8. 상위 정보 구조

현재 승인된 최상위 구조는 다음과 같다.

```text
Home
Work
Writing
Now
About
```

육아, AI, 게임, 생산성 등은 상위 메뉴가 아니라 Writing 내부의 주제/연재로 둔다.

각 페이지의 세부 구조와 관계는 다음 단계인 IA에서 확정한다.

## 9. 성공 기준

초기 성공을 트래픽으로 판단하지 않는다.

### 사이트 자체

- 처음 방문한 사람이 1분 안에 내가 누구인지 이해할 수 있다.
- 내가 중요하게 생각하는 Work를 2번 이하의 클릭으로 볼 수 있다.
- 글을 추가하기 위해 사이트 구조를 계속 수정할 필요가 없다.

### 콘텐츠

- 부담 없이 계속 게시할 수 있다.
- 육아, 일, 개인 프로젝트 등 서로 다른 글이 올라가도 사이트가 어색하지 않다.
- 시간이 지난 뒤 과거 글을 다시 읽고 생각의 변화를 확인할 수 있다.

### 개인적 가치

가장 중요한 성공 기준은 다음 질문이다.

> 인터넷에 무엇인가를 남기고 싶을 때 가장 먼저 생각나는 장소가 이 사이트인가?

## 10. 이 프로젝트의 목표가 아닌 것

초기 단계에서 다음을 목표로 하지 않는다.

- 퍼스널 브랜딩 전문가처럼 보이기
- 단기간 검색 유입 만들기
- 인플루언서 되기
- 콘텐츠 사업 수익화
- 기술적으로 인상적인 웹사이트 만들기
- 모든 경력을 완벽하게 정리하기
- 모든 생각을 기록하기

## 11. 개발 및 설계 방향

프로젝트의 승인된 기본 공정은 다음과 같다.

```text
Strategy
  ↓
IA
  ↓
Wireframe
  ↓
Build Spec
  ↓
Implementation
  ↓
Content
  ↓
Operation
```

### IA

무엇이 필요한지, 페이지와 정보가 어떤 구조와 관계를 가져야 하는지 정의한다.

### Wireframe

IA의 추상 구조를 사용자가 직접 확인하고 승인할 수 있는 시각적 구현 계약으로 바꾼다.

- 정본 도구: **Figma Starter 무료 플랜 ($0)**
- Low/Mid fidelity 수준을 기본으로 한다.
- 핵심 화면의 정보 위계, 섹션 순서, 레이아웃, 콘텐츠 밀도, 내비게이션, 주요 모바일 변화를 결정한다.
- Home은 초기 단계에서 2~3개의 구조 방향을 비교할 수 있다.
- 승인된 주요 화면은 필요 시 PNG snapshot으로 GitHub 저장소에 보존한다.
- 현재 기본 공정에는 별도의 고충실도 UI 디자인 단계를 두지 않는다.

### Build Spec

승인된 Strategy, IA, Wireframe을 실제 구현 가능한 기술적 계약으로 전환한다.

예상 항목:

- 기술 스택
- route와 콘텐츠 모델
- 승인 Wireframe 매핑
- responsive 기준
- typography/design token 구현
- component 구조
- SEO 최소 범위
- accessibility
- deployment
- v1 포함/제외 범위
- acceptance criteria

### Implementation

AI agent는 승인된 Strategy → IA → Wireframe → Build Spec 순으로 읽고 구현한다.

승인 문서와 다른 구조를 임의로 재설계하거나 요구되지 않은 기능을 추가하지 않는다.

## 12. Wireframe Tool Decision

Wireframe 도구는 **Figma Starter 무료 플랜**으로 확정한다.

선택 이유:

- 현재 프로젝트 규모에서 무료 플랜으로 충분하다.
- 별도 월 구독비가 필요하지 않다.
- 와이어프레임 이후 개발 handoff와 AI agent workflow로 연결하기 유리하다.
- Balsamiq의 유료 구독을 별도로 추가할 만큼 이번 프로젝트에서 얻는 추가 효익이 크지 않다.
- Penpot도 유효한 무료 대안이나, 현재 AI/개발 생태계 연계 측면에서 Figma를 우선한다.

Figma Professional 등 유료 플랜은 무료 플랜 제약이 실제 작업을 방해하는 경우에만 별도 검토한다.
