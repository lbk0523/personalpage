# Information Architecture

Status: APPROVED
Approved: 2026-08-19

## Purpose

이 문서는 개인 웹사이트 v1의 정보 구조와 각 화면의 역할을 정의한다.
라우트·문서·컴포넌트 식별자는 개발 편의를 위해 영어를 사용할 수 있지만, 실제 사용자-facing 웹페이지의 언어는 한국어를 기본으로 한다.

실제 메뉴명·섹션명·카피는 이 문서에서 확정하지 않는다. 해당 표현은 Wireframe 단계에서 한국 개인 웹사이트 레퍼런스를 조사한 뒤 시각적 맥락 속에서 결정한다.

## Core Structure

```text
/
├─ /work
│  └─ /work/[slug]
│
├─ /writing
│  └─ /writing/[slug]
│
├─ /now
└─ /about
```

Growth phase에서 필요할 경우 다음을 추가할 수 있다.

```text
/writing/topic/[slug]
/writing/series/[slug]
```

Topic/Series 화면은 콘텐츠가 충분히 축적되어 탐색 가치가 생기기 전에는 생성하지 않는다.

## Global Navigation

IA상의 식별자:

- Work
- Writing
- Now
- About

`Home`은 별도 메뉴 항목으로 두지 않고 사이트 이름 또는 로고를 통해 `/`로 이동한다.

실제 화면의 한국어/영문 라벨은 Wireframe 단계에서 결정한다.

---

## Home `/`

### Question

방문자가 다음 질문에 빠르게 답을 얻도록 한다.

> 이병관은 누구고, 무엇을 하는 사람이며, 왜 더 알아볼 만한가?

### Cold Start Structure

```text
Intro
↓
Selected Work
↓
Now
↓
Footer
```

초기에는 `Selected Writing`을 노출하지 않는다.

### Growth Structure

대표로 보여줄 만한 Writing이 축적되면 다음처럼 확장할 수 있다.

```text
Intro
↓
Selected Work
↓
Selected Writing
↓
Now
↓
Footer
```

`Selected Writing`은 최신순 자동 피드가 아니라 직접 큐레이션한 대표 콘텐츠를 보여준다.

### Intro

역할:
- 이름
- 현재의 직업적 정체성
- 한 문장 수준의 자기 설명
- Work 또는 About으로 이어지는 진입점

정확한 카피는 Content 단계에서 작성하고, 화면상 위계는 Wireframe 단계에서 결정한다.

### Selected Work

- 대표 작업 2~3개
- 최신순이 아닌 직접 큐레이션
- Work Detail로 연결

### Now Preview

- `/now`의 현재 관심과 활동 일부를 보여준다.
- 상세 내용으로 이동할 수 있어야 한다.

---

## Work `/work`

### Question

> 이 사람은 실제로 무엇을 해봤고, 어떻게 일하는가?

### Cold Start Structure

```text
Work Intro
↓
Work Cases
↓
Career / Background
```

### Work Intro

현재 역할과 직업적 흐름을 짧게 설명한다.

### Work Cases

회사 업무와 개인 프로젝트를 동일한 목록 안에서 다룬다.
필요한 경우 메타데이터로 `Professional`, `Personal` 등을 구분할 수 있다.

초기에는 Personal Projects를 별도 상위 섹션으로 분리하지 않는다.

### Career / Background

이력서 전체를 복제하지 않는다.
방문자가 경력 흐름을 이해하는 데 필요한 정도의 정보만 제공한다.

---

## Work Detail `/work/[slug]`

### Question

> 이 프로젝트에서 이병관은 무엇을 판단했고, 무엇을 기여했는가?

### Content Requirements

상세 사례는 다음 정보를 표현할 수 있어야 한다.

- Context
- My Role
- Problem
- Approach / Decisions
- Execution
- Outcome
- Reflection

위 항목을 고정된 UI 섹션 수로 강제하지 않는다.
프로젝트 성격에 따라 묶거나 생략할 수 있지만, 최소한 `판단 과정`, `기여`, `결과 또는 학습`이 드러나야 한다.

---

## Writing `/writing`

### Question

> 이 사람은 무엇에 관심이 있고 어떻게 생각하는가?

### Cold Start Structure

```text
Writing Intro
↓
Writing List
```

초기에는 다음을 노출하지 않는다.

- Featured Writing
- Topic Navigation
- Series Navigation
- 별도 Notes 영역
- 별도 Essays 영역

콘텐츠가 적은 상태에서 분류 UI를 먼저 만들지 않는다.

### Writing Types

콘텐츠 모델은 최소한 다음 타입을 지원한다.

- Essay
- Note

두 타입은 동일한 목록과 상세 route를 사용할 수 있다.
실제 화면에서 type을 얼마나 강조할지는 Wireframe 단계에서 결정한다.

---

## Writing Detail `/writing/[slug]`

### Structure

```text
Article Header
↓
Body
↓
Optional Navigation
```

### Supported Metadata

- title
- date
- type
- topic
- series (optional)

메타데이터를 모두 화면에 노출할 필요는 없다.
실제 노출 방식과 순서는 Wireframe 단계에서 결정한다.

### Parenting / Series Rule

`아빠들의 육아 대화`는 별도 최상위 페이지나 별도 콘텐츠 타입으로 만들지 않는다.
Writing 내부의 topic 또는 series metadata로 시작한다.

예:

```text
topic: parenting
series: 아빠들의 육아 대화
```

콘텐츠가 충분히 쌓인 이후에만 series/topic landing page를 검토한다.

---

## Topic / Series Archive — Growth Capability

예상 route:

```text
/writing/topic/[slug]
/writing/series/[slug]
```

Cold Start에서는 화면을 만들지 않는다.
같은 주제나 연재의 콘텐츠가 축적되어 별도 탐색이 실제 사용자에게 가치가 생긴 경우에만 활성화한다.

---

## Now `/now`

### Question

> 이병관은 지금 무엇을 하고 있는가?

현재 집중하는 일, 관심, 프로젝트, 삶의 변화를 짧게 보여준다.

특정한 `Work / Exploring / Making / Life` 같은 카테고리 구조를 IA에서 강제하지 않는다.
핵심 속성은 `현재성`이다.

업데이트 시점을 확인할 수 있어야 한다.

---

## About `/about`

### Question

> 업무 이력만으로는 알기 어려운 이병관은 어떤 사람인가?

### Structure

```text
Introduction
↓
Background / Perspective
↓
Contact
```

Work에서 다룬 상세 경력표를 반복하지 않는다.
개인적 배경과 생각하는 방식, 관심사를 이해하는 데 필요한 정보에 집중한다.

---

## Footer

최소한으로 유지한다.

필요한 경우 다음을 포함할 수 있다.

- Copyright
- Email
- GitHub
- RSS

실제로 운영하지 않는 외부 채널을 미리 추가하지 않는다.

---

## Core User Journeys

### A. Professional Visitor

```text
Home
→ Selected Work
→ Work Detail
→ About
```

약 2클릭 안에 실제 경험과 판단 능력을 확인할 수 있어야 한다.

### B. Writing Visitor

```text
Writing Detail
→ Writing
→ Other Writing
→ About
```

특정 육아 글 등으로 유입된 방문자도 사이트 전체를 탐색하면서 작성자의 직업적·개인적 맥락을 이해할 수 있어야 한다.

### C. Existing Acquaintance

```text
Home
→ Now
→ Writing / Work
```

현재 관심사를 출발점으로 다른 영역으로 이동할 수 있어야 한다.

---

## Cold Start Principle

> IA는 미래의 확장을 허용하고, 실제 UI는 현재 존재하는 콘텐츠만큼만 보여준다.

| Capability | Cold Start | Growth |
|---|---|---|
| Home Writing | 숨김 | 대표 글 큐레이션 |
| Writing Featured | 없음 | 필요 시 추가 |
| Topics | metadata only | 탐색 UI 제공 |
| Series | metadata only | landing page 가능 |
| Personal Projects | Work와 혼합 | 필요 시 독립 섹션 |
| Related Writing | 선택 사항 | 콘텐츠 증가 후 제공 |

## Wireframe Screen Inventory

Wireframe 단계의 기본 화면은 다음 7개다.

```text
WF-01 Home
WF-02 Work
WF-03 Work Detail
WF-04 Writing
WF-05 Writing Detail
WF-06 Now
WF-07 About
```

별도 모바일 확인 우선순위:

```text
Home
Writing
Writing Detail
```

모든 페이지를 Desktop/Mobile 두 벌로 만들 필요는 없다.

---

## Explicitly Out of v1 IA

초기에는 다음 독립 페이지를 만들지 않는다.

- Resume
- Projects
- Parenting
- Ayukdae
- Archive
- Tags
- Uses
- Bookshelf
- Newsletter
- Contact

필요성이 실제로 확인되기 전까지 Work / Writing / Now / About 안에서 수용한다.

---

## Deferred to Wireframe

다음은 IA에서 의도적으로 미결정 상태로 남긴다.

- 실제 내비게이션 라벨과 언어
- 한국어 섹션명 및 카피
- Home의 시각적 정보 위계
- Work의 카드/목록/editorial 표현 방식
- Writing의 archive 표현 방식
- 콘텐츠 metadata의 실제 노출 정도
- 직업적 포트폴리오와 개인적 글쓰기 공간 사이의 시각적 균형

Wireframe 단계에서는 한국인이 운영하는 개인 웹사이트 사례를 우선적으로 조사하여 위 결정을 위한 레퍼런스로 사용한다.
